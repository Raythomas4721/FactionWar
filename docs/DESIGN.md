# 陣營小人戰鬥模擬（獸人／精靈／矮人／人類）— 可行性與實作規劃

## Context
使用者想做一款「不同陣營小人自動互動與戰鬥」的模擬遊戲：四個種族，每個小人有智慧、力量、敏捷等屬性，屬性會影響**造出的武器、能蓋的建築、是否容易生病、能否遊說結盟、策反敵人**。目前沒有既有程式碼（新專案），本文件評估可行性並給出可執行的分階段方案。

## 已確認的決定
- **玩家角色：兩種都要**——先做上帝觀察模式；指揮模式之後再加。為此模擬核心從一開始就透過「指令佇列」(`issueCommand(factionId, cmd)`) 接收行動，AI 和玩家用同一套指令，日後加指揮模式不用重寫。
- **本次實作範圍：M1 + M2**（戰鬥沙盒＋經濟／製造／建築）。M3–M5 只保留介面與欄位，不實作。
- **畫面：簡單色塊**（Canvas 2D，小人＝種族色圓點＋武器小符號，建築＝方塊）。

## 可行性結論：可行，建議分階段做
- 這類遊戲屬於「Agent-based 模擬」（類似 WorldBox、RimWorld 的縮小版）。每個小人是一個帶屬性的資料物件，每一個 tick 跑一輪「系統」更新，技術上不難。
- **真正的難點不是寫程式，而是：**
  1. **平衡**：某一族很容易一面倒獲勝 → 需要「無畫面批次模擬器」跑上千場統計勝率來調參。
  2. **可觀察性**：智慧影響武器品質這類效果，如果畫面上看不到，玩家感受不到 → 需要事件日誌與單位檢視面板。
  3. **範圍膨脹**：五個系統（戰鬥／製造／建築／疾病／外交）一起做會失控 → 每階段都要能玩。

## 技術選型（沿用你 WuxiaFantasy 的技術棧）
- Vite + React + TypeScript，Vitest 做測試。
- **模擬核心為純 TS（`src/sim/`），不依賴 React/畫面**：可單元測試、可無畫面批次跑。
- 畫面用 Canvas 2D 俯視圖（小人用色塊／圓點＋種族圖示），React 負責側邊面板。
- 固定 tick（例如每秒 10 tick，可加速 1x/2x/5x/暫停）＋**種子亂數**（同種子可重播同一場戰局，方便除錯）。
- 規模：數百個小人 Canvas 沒問題；超過約 2000 才需要空間格分割優化。

## 核心資料模型
**屬性（五項）**：力量 STR、敏捷 AGI、智慧 INT、體質 CON（對應「會不會生病」）、魅力 CHA（對應「遊說／策反」）。

| 種族 | STR | AGI | INT | CON | CHA | 特色 |
|---|---|---|---|---|---|---|
| 獸人 | 高 | 中 | 低 | 高 | 低 | 人口成長快、近戰強、科技慢、易被策反 |
| 精靈 | 低 | 高 | 高 | 中 | 中 | 弓箭專精、高科技、人口少 |
| 矮人 | 高 | 低 | 中 | 最高 | 低 | 鍛造／重甲加成、幾乎不生病、城牆建築強 |
| 人類 | 中 | 中 | 中 | 中 | 高 | 均衡、外交與策反最強 |

個體屬性 = 種族基礎值 ± 隨機浮動，所以同族也有聰明的獸人、笨拙的精靈。

- **Unit（小人）**：id、陣營、種族、屬性、HP、飢餓、健康／疾病狀態、忠誠度、職業（工人／戰士／工匠／外交官）、裝備、位置、當前行為。
- **Faction（陣營）**：資源（木、石、礦、糧）、科技等級（由陣營智慧平均＋研究累積）、建築列表、與其他陣營的關係值。

## 系統設計（每個 tick 依序執行）
1. **AI 決策**：個體用 Utility AI（每個可做的行為算分數，選最高分），陣營層用簡單策略 AI（依資源與威脅決定要造兵、蓋建築、或派外交官）。
2. **移動**：格子地圖＋A* 尋路。
3. **經濟**：工人採集資源回基地。
4. **製造（武器）**：武器品質 = f(工匠 INT、STR、陣營科技、是否有鍛造坊)。武器樹：木棒 → 銅劍 → 鐵劍 → 精鋼；弓 → 長弓 → 弩。種族加成：精靈弓類、矮人錘／重甲、獸人巨斧。
5. **建築**：以科技等級（智慧）解鎖：營帳 → 房屋 → 鍛造坊 → 城牆／箭塔 → 醫院／神殿 → 外交館。
6. **疾病**：每 tick 感染機率 = 人口密度 × (1 − 衛生建築加成) × (1 − CON 抗性)；會傳染、會降低戰力。矮人可設定對特定疾病免疫，達成「不會生病」的設定。
7. **戰鬥**：命中率 = 攻方 AGI vs 守方 AGI；傷害 = STR ＋ 武器 − 護甲 − CON 減免；士氣低會逃跑。
8. **外交（結盟）**：外交官前往他陣營，成功率 = 外交官 CHA ＋ 共同敵人加成 ＋ 實力差 − 種族宿怨表（如 精靈↔矮人、獸人↔所有人）。盟友不互攻、會支援。
9. **策反**：每個小人有忠誠度（受糧食、勝敗、領袖 CHA 影響）。敵方說客以 CHA＋INT 降低目標忠誠，低於門檻就倒戈換陣營（顏色改變），也可能整個盟約破裂。

## 分階段 Roadmap
- **M1 戰鬥沙盒（最小可玩）**：地圖、四族小人、屬性、移動與戰鬥，自動對戰看誰贏；加速／暫停、事件日誌、點擊小人看屬性。
- **M2 經濟與製造**：資源採集、武器品質與種族專精、建築與科技解鎖。
- **M3 疾病與人口**：出生、飢餓、疾病傳播、醫院。
- **M4 外交與策反**：關係值、結盟、說客、忠誠度與倒戈。
- **M5 調參與玩家介入**：開局設定（各族人數、屬性倍率）、上帝之手（降瘟疫／空投資源）、批次平衡模擬器報表。

## 驗證方式
- `npm test`：各系統公式單元測試（如「INT 較高的工匠造出的武器品質較高」「CON 高的矮人感染率較低」「忠誠度低於門檻會倒戈」）。
- `npm run balance`：無畫面跑 500 場，四族勝率應落在約 15%–35% 之間，否則調參。
- `npm run dev` 在內建瀏覽器開啟，實際觀看一場戰局，確認事件日誌出現製造、生病、結盟、倒戈等事件。
